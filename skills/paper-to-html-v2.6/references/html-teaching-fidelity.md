# 从讲解定稿到HTML的内容保真

## 目标与边界
防止聊天或内部样稿讲得充分，生成HTML却只剩一小段。不能仅靠“不要压缩”提示；把写作与装配分开，并让丢失内容阻止发布。保真比较证明指定定稿未被改变，不证明定稿本身科学正确或读者已理解。结构/语义/内容传输/实际显示分别验收。

## 定稿先行
1. 从来源建立讲解单位和证据台账。按完整单位分批写作，复杂关键图先校准；不把全文翻译、术语发现、逐图解读、布局和脚本交给同一次自由生成。
2. 充分分析后编辑成简洁短块。确认对象、参照、读数、必要统计、作者例子和关键反例仍能接上判断。不是把长段原封塞进网页，也不是装配时再概括。
3. 保存经核对的定稿content.html及按需使用的blocks数据。每个面板/reader-text/可标黄叶块使用稳定id，原图注、翻译、总结、作者判断分开。维护时与修改前逐项比较三项前置内容；出现科学错误需更正时另行明确更正内容与依据，不悄悄改写。
4. 从这份定稿创建内部基线，再开始装配；后续如修订定稿，保留旧基线并复核差异后显式生成新基线。不能从疑似被压缩的最终HTML反向重建基线来消除报错。

## 可执行流程
```sh
python scripts/teaching_contract.py --html work/content.html --snapshot work/teaching-baseline.json
python scripts/build_reader.py --content work/content.html --paper-id 本文稳定ID --out work/paper-reading-working.html --teaching-baseline work/teaching-baseline.json
python scripts/publish_reader.py --root outputs/论文目录 --source work/paper-reading-working.html --title 文章简称 --teaching-baseline work/teaching-baseline.json
```
路径按当前项目。需要concepts、figure-data或reader-url时在build命令追加对应参数。基线是内部校验材料，不在阅读页显示，不构成第二个阅读HTML。

新v2讲解缺基线时，build和publish拒绝写入。旧v1仍兼容；维护旧稿可显式传基线接受同一比较。teach结构命令只生成基线不代表语义通过。

`teaching_fidelity.py`按稳定面板/独立讲解单元提取唯一reader-text，缺失或重复容器直接拒绝创建基线。比较顺序文本、数字、段落/列表/表格等结构、稳定块id、前置保护标识及显式隐藏属性/行内样式（含影响该单元的上层容器）。术语链接和无意义空白变化允许通过；丢面板、删块、换数字、重排或添加hidden会报错。面板初始hidden可以用于正常切换，只要求装配前后保持一致；实际切换后能否显示另测。整图总览的reader-text也纳入比较。它不比较图片像素、任意全局CSS效果或运行后状态，不能替代实际查看。

## 实际显示仍要检查
同一最终稿在桌面浏览器切换每个面板，核对图文同步、全部定稿块可见或能正常滚动到达、末尾段和表格完整、无意外折叠、遮挡或裁切。图中文字辨认不了时先处理原图。检查默认窗口及200%缩放后关键内容的到达情况；不因字符在DOM里就判可读。必要时截图核对。

没有逐面板实际显示记录就标未测，不能用合成浏览器测试冒充真实论文已逐图验收。新版Skill的合成回归仅验证机制。科研来源、逐图语义、程序比对、实际显示和用户理解各自注明范围及通过/失败/未测/缺资料。

## 失败处理
差异或显示问题未解决前，不覆盖唯一正式入口。先定位在哪个单位、哪个块丢失或被隐藏，回到该单位补齐再重验；不把差异默认为“自动精简”。发布校验失败保留原入口。任务压力或执行限制导致未完成时交付明确范围工作稿，不宣称全篇合格。
